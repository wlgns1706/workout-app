# 개인 운동 앱 버전 1 설계 문서

- 작성일: 2026-09-30
- 상태: 사용자 검토 대기

## 1. 목적

- 사용자는 본인 한 명이다. Android 폰에서 주로 쓴다.
- **단기 목표**: 2027-01-31 결혼식 전까지 다이어트를 돕는다.
- **장기 목표**: 결혼식 이후에도 운동 퍼포먼스를 기록하면서 꾸준히 성장한다.
- 버전 1의 성공 기준
  - 2026-10-05부터 헬스장에서 이 앱만으로 그날의 운동을 확인하고 세트를 기록할 수 있다.
  - 매일 체중과 컨디션을 10초 안에 입력할 수 있다.
  - 폰을 바꾸거나 잃어버려도 백업 파일로 기록을 복원할 수 있다.

## 2. 범위

### 버전 1에 포함

1. 운동 프로그램 가져오기와 일정(16주) 설정
2. 오늘 할 운동 표시와 세트 기록
3. 못 한 운동을 D5/D6에서 이어서 기록
4. 체중과 일일 체크 입력
5. 백업 내보내기와 가져오기

### 버전 2로 미룸

- 식단 (끼니별 칼로리·탄단지 입력, 자주 먹는 음식 저장)
- 인바디 주 1회 입력 (체중, 골격근량, 체지방량, 체지방률)
- 추정 1RM 추이 그래프

> 버전 1의 완성도가 확보되면, 버전 2를 진행해야 한다고 사용자에게 먼저 알린다. (사용자 요청)

### 만들지 않음 (요청이 오면 그때 검토)

- 볼륨 통계, 원판 계산기, 대체 종목 기록, 운동 종료 요약 화면
- 눈바디 사진, 둘레 기록
- 클라우드 동기화, 로그인, PC용 화면
- 앱 안에서 엑셀 파일을 직접 읽는 기능

## 3. 운동 프로그램의 구조 (엑셀 분석 결과)

- 엑셀 파일은 4개다: 근비대 One, 근비대 기본, 스트렝스 One, 스트렝스 기본.
- 파일 하나는 블록 3개로 이루어진다. 블록 하나는 4주다.
  - 블록의 기본 RPE는 @7, @8, @9로 올라간다.
  - 블록 3의 4주차는 "완전 휴식"이다.
- 한 주는 D1~D6이다.
  - D1~D4는 종목이 정해져 있다.
  - D5와 D6은 선택이고, 종목 대신 옵션 텍스트가 있다.
- 종목 하나는 세트 줄 1개 이상으로 이루어진다. 세트 줄은 세트 수, 반복(문자열: "8~12", "30", "30s"), RPE("@7")를 가진다.
- 운동일마다 저강도 유산소 줄이 있다(권장 또는 필수).
- 엑셀에는 RPE × 반복 수 → 1RM 대비 비율표(RPE 6.5~10, 1~12회)가 있다.

### 이번 일정

- 프로그램: 근비대 One
- 시작일: 2026-10-05(월)
- 블록 순서: 1 → 1 → 2 → 3 (총 16주)
- 종료일: 2027-01-24(일)
- 결혼식 이후에는 블록 순서를 1 → 2 → 3으로 두고, 12주마다 다른 프로그램으로 바꿀 수 있다.

## 5. 화면

하단 탭은 4개다.

### 5.1 오늘

- 상단에 현재 위치를 표시한다. 예: "5주차 / 16주 · 블록 1(2회차) · 1주차 · @7"
- 이번 주의 D1~D6을 버튼으로 보여주고, 완료 여부를 표시한다.
- 다음에 할 요일을 기본으로 선택한다.
  - D1~D4 중 완료하지 않은 가장 앞 요일이다.
  - D1~D4를 모두 끝냈으면 D5를 선택한다.
- 요일을 누르면 운동 기록 화면(5.2)이 열린다.
- 시작일 전이면 "10월 5일에 시작합니다"와 남은 일수를 보여준다.
- 일정이 끝났으면 새 일정을 만들도록 안내한다.
- 완전 휴식 주에는 "이번 주는 완전 휴식입니다"를 보여준다.

### 5.2 운동 기록 화면

- 종목을 프로그램 순서대로 보여준다.
- 화면 위에 진행률을 표시한다. 예: "7 / 12 종목"
- 끝난 종목은 한 줄로 접는다. 누르면 다시 펼친다.
- 운동 기록 화면이 열려 있는 동안 폰 화면이 꺼지지 않게 한다.

**종목 카드**

- 종목 이름
- 단위 선택(kg / lbs). 종목별로 기억한다.
- 휴식 시간 설정. 종목별로 기억한다. 기본값은 120초다.
- 고정 메모(기구 세팅 등). 종목별로 기억하고, 그 종목이 나올 때마다 보여준다.
- 지난 기록: 같은 종목을 마지막으로 한 날의 본 세트와 실패 세트를 한 줄로 보여준다. 예: "지난번(9/28) 60kg×10, 60kg×9"
- "나중에 하기" 버튼: 이 종목을 목록 맨 아래로 옮긴다.
- "세트 추가" 버튼: 처방에 없는 세트(주로 웜업)를 추가한다. 추가한 세트는 삭제할 수 있다.

**세트 줄**

`[세트 번호/타입] [무게: −5 −0.5 값 +0.5 +5] [횟수: − 값 +] [RPE] [✓]`

| 요소 | 동작 |
|---|---|
| 처방 표시 | 세트 줄 위에 처방을 보여준다. 예: "8~12회 @7" |
| 세트 타입 | 세트 번호를 누르면 웜업(W), 본 세트(숫자), 실패(F) 중에서 고른다. 기본은 본 세트다. |
| 무게 | kg일 때 증감 폭은 0.5와 5다. lbs일 때는 1과 10이다. 숫자를 누르면 직접 입력한다. |
| kg 환산 | 단위가 lbs이면 무게 아래에 kg 환산값을 작게 보여준다. 소수 첫째 자리까지다. |
| 횟수 | 증감 폭은 1이다. 숫자를 누르면 직접 입력한다. |
| RPE | 선택 입력이다. 6.5~10을 0.5 단위로 고른다. |
| 추천 무게 | 무게 칸에 추천값을 흐리게 미리 채운다. 값을 바꾸지 않고 체크하면 그 값으로 기록한다. |
| 체크(✓) | 누르면 그 세트를 수행으로 기록하고 휴식 타이머를 시작한다. 다시 누르면 취소하고 타이머도 멈춘다. |
| 다음 세트 자동 채우기 | 세트를 체크하면 같은 종목의 다음 세트에 방금 입력한 무게와 횟수를 채운다. |
| 개인 기록 표시 | 체크한 세트의 추정 1RM이 그 종목의 이전 최고값을 넘으면 "PR" 표시를 붙인다. |

- 세트 메모는 세트 줄을 길게 누르거나 메모 아이콘을 눌러 입력한다.
- 모든 입력은 바꾸는 즉시 저장한다.

**휴식 타이머**

- 화면 하단에 남은 시간을 표시한다.
- "+30초"와 "건너뛰기" 버튼이 있다.
- 끝나면 진동과 짧은 소리로 알린다.
- 종료 시각을 기준으로 계산한다. 다른 앱에 다녀와도 남은 시간이 정확하다.
- 새 세트를 체크하면 타이머를 새로 시작한다.

**유산소와 요일 마무리**

- 유산소 줄은 했는지 체크만 한다.
- 그날 메모를 적을 수 있다.
- "운동 완료" 버튼을 누르면 완료 시각을 저장한다.
  - 기록하지 않은 세트가 남아 있으면 "남은 운동은 D5/D6에서 이어서 할 수 있어요"라고 알려주고 완료 처리한다.
- 운동 시간은 첫 세트 체크 시각부터 완료 시각까지로 자동 기록한다.

### 5.3 D5와 D6 화면

- 맨 위에 "이번 주에 못 한 운동"을 보여준다.
  - 이번 주 D1~D4의 처방 세트 중 체크하지 않은 것을 종목별로 모은다.
  - 5.2와 같은 종목 카드로 바로 기록한다.
  - 기록은 원래 요일의 처방에 붙는다. 실제 수행 날짜와 수행한 요일(D5 또는 D6)을 함께 저장한다.
- 그 아래에 엑셀의 옵션 텍스트를 보여주고, 무엇을 했는지 고른다. 여러 개를 고를 수 있다.
- 그날 메모와 "운동 완료" 버튼이 있다.

### 5.4 일정

- 16주를 주 단위 목록으로 보여준다. 각 주에 날짜 범위, 블록, 주차, 기본 RPE를 표시한다.
- 각 주의 D1~D6 완료 여부를 표시한다.
- 어느 주의 어느 요일이든 눌러서 기록을 보거나 수정할 수 있다. 밀린 운동은 여기서 기록한다.

### 5.5 몸 상태

- 오늘 날짜의 입력 칸을 보여준다.
  - 체중 (kg, 소수 첫째 자리)
  - 수면 시간 (시간, 0.5 단위)
  - 영양, 동기, 자신감, 스트레스, 피로도 (각 1~10)
- 모든 칸은 선택 입력이다. 체중만 적어도 저장된다.
- 날짜를 바꿔서 지난 날의 기록을 입력하거나 고칠 수 있다.
- 아래에 최근 기록을 목록으로 보여준다.

### 5.6 설정

- 프로그램: 가져온 프로그램 목록, 프로그램 파일 가져오기
- 일정: 현재 일정 확인, 새 일정 만들기(프로그램, 시작일, 블록 순서)
- 백업: 내보내기, 가져오기, 마지막 백업 날짜
- 앱 버전 표시

### 5.7 처음 실행할 때

1. 프로그램 파일을 가져오도록 안내한다.
2. 프로그램, 시작일, 블록 순서를 골라 일정을 만든다.
3. "오늘" 탭으로 이동한다.

## 6. 데이터 모델

IndexedDB에 저장하는 테이블이다.

| 테이블 | 주요 필드 | 설명 |
|---|---|---|
| `programs` | id, name, blocks | 가져온 프로그램. 읽기 전용이다. |
| `plans` | id, programId, startDate, blockSequence, createdAt | 일정. blockSequence는 [1, 1, 2, 3] 같은 배열이다. |
| `setLogs` | 아래 참고 | 세트 하나의 기록 |
| `dayLogs` | planId, planWeek, dayNo, startedAt, finishedAt, cardioDone, optionChoices, note, exerciseOrder | 요일 하나의 기록 |
| `bodyLogs` | date, weightKg, sleepHours, nutrition, motivation, confidence, stress, fatigue | 날짜별 몸 상태 |
| `exerciseSettings` | exerciseName, unit, restSeconds, note | 종목별 설정 |
| `meta` | key, value | 마지막 백업 시각 등 |

**프로그램 구조**

```
program
└─ blocks[]            블록 1~3
   └─ weeks[]          1~4주차
      └─ days[]        D1~D6
         ├─ optional   선택 요일인지
         ├─ exercises[]
         │  ├─ name
         │  └─ rows[]  { sets, reps, rpe }
         ├─ cardio     { label, detail, required }
         └─ optionsText  D5/D6의 옵션 텍스트
rpeChart               RPE × 반복 수 비율표
```

**setLogs 필드**

| 필드 | 설명 |
|---|---|
| id | 자동 생성 |
| planId, planWeek, dayNo | 일정의 몇 주차(0~15), 어느 요일의 처방인지 |
| exerciseIndex, rowIndex, setIndex | 어느 종목, 어느 세트 줄, 몇 번째 세트인지. 추가한 세트는 rowIndex가 없다. |
| exerciseName | 지난 기록과 개인 기록을 찾을 때 쓴다. |
| type | warmup, work, failure |
| weight, unit, weightKg | 입력한 값과 단위, kg 환산값 |
| reps, rpe, memo | rpe와 memo는 선택이다. |
| done, doneAt | 체크 여부와 체크한 시각 |
| performedDayNo | 실제로 수행한 요일. D5에서 이어서 했으면 5다. |

**설계 의도**

- "블록 1을 2번"은 프로그램을 고치지 않고 `blockSequence`로 표현한다.
- 세트 기록은 일정의 주차에 붙는다. 같은 블록을 두 번 해도 기록이 따로 남는다.
- 지난 기록과 개인 기록은 종목 이름으로 찾는다. 요일이나 프로그램이 달라도 이어진다.
- 버전 2의 식단과 인바디는 테이블을 추가하면 된다. 기존 테이블은 바꾸지 않는다.

## 7. 계산 규칙

### 7.1 일정 계산

- 일정 주차 = (오늘 − 시작일)을 7로 나눈 몫. 0부터 센다.
- 블록 = blockSequence[일정 주차 ÷ 4의 몫]
- 블록 안의 주차 = (일정 주차 ÷ 4의 나머지) + 1
- 오늘이 시작일보다 앞이면 "시작 전"이다.
- 일정 주차가 blockSequence 길이 × 4 이상이면 "종료"다.

### 7.2 단위 환산

- 1 lb = 0.45359237 kg
- 화면에는 kg을 소수 첫째 자리까지 보여준다. 저장은 반올림하지 않은 값으로 한다.

### 7.3 추정 1RM

- 추정 1RM = 무게(kg) ÷ 비율(반복 수, RPE)
- 비율은 프로그램 파일의 RPE 차트에서 찾는다.
- RPE는 입력값을 쓴다. 입력하지 않았으면 처방 RPE를 쓴다. 실패 세트는 10으로 본다.
- RPE가 6.5보다 작으면 6.5로 본다.
- 반복 수가 12회를 넘으면 추정 1RM을 계산하지 않는다.
- 웜업 세트는 계산하지 않는다.

### 7.4 추천 무게

1. 같은 종목에서 추정 1RM을 계산할 수 있는 가장 최근 수행일을 찾는다.
2. 그날 세트들의 추정 1RM 중 가장 큰 값을 기준으로 쓴다.
3. 이번 처방의 목표 반복 수를 정한다.
   - 범위("8~12")이면 가운데 값을 쓴다. 가운데가 정수가 아니면 올림한다. 예: "3~6"은 5
   - 숫자 하나면 그 값을 쓴다.
4. 추천 무게 = 기준 추정 1RM × 비율(목표 반복 수, 처방 RPE)
5. kg이면 2.5 단위로, lbs이면 5 단위로 반올림한다.

- 목표 반복 수가 12회를 넘거나 시간("30s")이면 추천하지 않고, 지난번 무게를 미리 채운다.
- 같은 종목의 기록이 없으면 아무것도 채우지 않는다.
- 같은 종목의 두 번째 세트부터는 "다음 세트 자동 채우기"가 추천보다 우선한다.

### 7.5 요일 완료와 못 한 운동

- 처방 세트는 세트 줄의 세트 수만큼 있다. "세트 추가"로 넣은 세트는 처방 세트로 세지 않는다.
- 처방 세트 자리의 타입을 웜업이나 실패로 바꿔도 처방 세트로 센다. 웜업은 "세트 추가"로 넣는 것이 기본 사용법이다.
- 요일은 "운동 완료"를 누르면 완료다.
- "이번 주에 못 한 운동"은 같은 일정 주차의 D1~D4에서 체크하지 않은 처방 세트다. 요일의 완료 여부와 관계없이 모은다.

### 7.6 개인 기록

- 종목별 최고 추정 1RM을 기준으로 한다.
- 체크한 세트의 추정 1RM이 그 세트 이전의 최고값보다 크면 PR로 표시한다.
- 그 종목의 첫 기록에는 표시하지 않는다.

## 8. 파일 형식

### 8.1 프로그램 파일

- 확장자는 `.json`이다. 엑셀 하나가 파일 하나가 된다.
- 최상위에 `type: "workout-program"`과 `formatVersion: 1`을 둔다.
- PC에서 Python 변환 스크립트로 만든다. 스크립트는 저장소에 넣고, 결과 파일은 넣지 않는다.
- 사용자는 이 파일을 폰으로 옮겨서(구글 드라이브 등) 앱에서 가져온다.

### 8.2 백업 파일

- 확장자는 `.json`이다.
- 최상위에 `type: "workout-backup"`, `formatVersion`, `exportedAt`을 둔다.
- 모든 테이블의 내용을 담는다. 프로그램도 포함한다.
- 파일 이름은 `workout-backup-YYYY-MM-DD.json`이다.

### 8.3 가져오기 동작

- 파일의 `type`을 보고 프로그램인지 백업인지 구분한다.
- 프로그램 파일: 같은 id의 프로그램이 있으면 덮어쓸지 확인한다.
- 백업 파일: 기록 개수와 기간을 보여주고, 현재 데이터를 전부 바꿀지 확인한다. 확인하면 한 번의 트랜잭션으로 교체한다.
- 형식이 맞지 않거나 `formatVersion`이 앱보다 높으면 거부하고 이유를 보여준다. 기존 데이터는 바꾸지 않는다.

## 9. 데이터 보호와 오류 처리

- 처음 실행할 때 브라우저에 영구 저장을 요청한다(`navigator.storage.persist`).
- 마지막 백업 후 7일이 지나면 앱 상단에 백업 알림 배너를 띄운다. 기록이 하나도 없으면 띄우지 않는다.
- 무게와 횟수는 0 이상만 받는다. 범위를 벗어난 점수는 받지 않는다.
- 저장에 실패하면 화면에 오류 메시지를 보여준다. 조용히 넘어가지 않는다.
- 데이터 구조가 바뀌면 Dexie 버전 마이그레이션으로 기존 기록을 변환한다.
- 새 버전이 배포되면 "새 버전이 있어요" 배너를 띄우고, 누르면 갱신한다.
- 화면 켜짐 유지, 진동 기능을 지원하지 않는 환경에서는 그 기능만 빼고 동작한다.

## 10. 코드 구조

```
src/
  domain/        순수 계산. 화면이나 저장소에 의존하지 않는다.
    schedule.ts      일정 계산 (7.1)
    units.ts         단위 환산 (7.2)
    e1rm.ts          추정 1RM, 추천 무게, 개인 기록 (7.3, 7.4, 7.6)
    progress.ts      요일 완료, 못 한 운동 (7.5)
    reps.ts          반복 문자열 해석 ("8~12", "30s")
  db/            Dexie 스키마와 테이블별 읽기·쓰기
  io/            프로그램 가져오기, 백업 내보내기·가져오기, 형식 검증
  features/      화면별 컴포넌트
    today/  workout/  schedule/  body/  settings/  onboarding/
  ui/            공용 컴포넌트 (숫자 조절 버튼, 타이머, 배너)
tools/
  convert_program.py   엑셀 → 프로그램 파일
```

- `domain`은 입력과 출력이 분명한 함수로만 이루어진다. 자동 테스트의 중심이다.
- 화면은 `db`와 `domain`을 통해서만 데이터를 다룬다.

## 11. 테스트

**자동 테스트 (Vitest)**

- 일정 계산: 시작 전, 첫날, 블록 경계, 블록 1 반복 구간, 완전 휴식 주, 종료 후
- 단위 환산: lbs → kg, 표시 반올림
- 반복 문자열 해석: "8~12", "30", "30s", "3~6"
- 추정 1RM: 차트 값과 일치하는지, RPE 미입력, 실패 세트, 12회 초과, 웜업 제외
- 추천 무게: 본문 예시(60kg × 10회 @7 → 8~12회 @8), 기록 없음, 12회 초과, lbs 반올림
- 못 한 운동: 일부만 체크한 종목, 웜업과 추가 세트 제외, D5에서 기록한 뒤 목록에서 사라지는지
- 개인 기록: 첫 기록, 갱신, 미갱신
- 백업: 내보낸 뒤 가져오면 모든 테이블이 같은지, 잘못된 파일 거부 시 기존 데이터 유지

**변환 스크립트 검증 (PC에서 실행)**

- 변환 결과의 요일 수, 종목 수, 세트 줄이 엑셀과 일치하는지 확인한다.
- 4개 파일 모두 변환되는지 확인한다.

**직접 확인**

- 브라우저에서 폰 크기로 열어 주요 흐름을 눌러 본다: 처음 실행, 세트 기록과 타이머, 나중에 하기, D5에서 이어 하기, 몸 상태 입력, 백업 내보내기와 가져오기
- 실제 폰에 설치한 뒤 오프라인 동작, 화면 켜짐 유지, 진동을 확인한다.

## 12. 배포

- GitHub 공개 저장소에는 코드만 올린다.
- `.gitignore`로 엑셀 파일과 프로그램 파일을 제외한다.
- main 브랜치에 올리면 GitHub Actions가 테스트를 돌리고 GitHub Pages에 배포한다.
- 사용자가 직접 할 일
  1. PC에서 GitHub 로그인 승인
  2. 폰 크롬에서 앱 주소를 열고 "홈 화면에 추가"
  3. 프로그램 파일을 폰으로 옮겨서 앱에서 가져오기

## 13. 알려진 제약

- 크롬에서 "사이트 데이터 삭제"를 하면 기록이 지워진다. 백업으로 대비한다.
- 폰 화면이 꺼지거나 앱이 백그라운드에 있으면 타이머 알림이 늦을 수 있다. 운동 기록 화면에서는 화면을 켜 둔다.
- 앱 주소를 아는 사람은 앱을 열 수 있다. 다만 프로그램과 기록은 각자의 폰에만 있으므로 보이지 않는다.
- 일정상 시간이 부족하면 추천 무게(7.4)를 10/5 이후 업데이트로 미룬다. 첫 주에는 지난 기록이 없어 추천이 나오지 않으므로 사용에 지장이 없다.
